# Reflection

The most difficult concept for me was the many-to-many relationship in databases, because I could not see how two tables could connect without storing a list in one cell. I overcame it by drawing the students, courses and enrolments tables on paper, filling them with real rows, and then writing the JOIN queries and checking the results. Once I saw that the join table holds one row for each pair, it made sense. I used the same idea later for notes and tags, and for orders and seats.

Based on the feedback I received, I would improve the explanation of my architecture diagram in the capstone. I tried to cover every component quickly, so my reasons for some of them were not clear. Next time I would start with the simplest design, add one component at a time, and say which problem each one solves. I would also show the request in the Network tab during the API demo, so the audience can see it working.

Next I want to learn Node.js and Express, so I can turn my QuickNotes API design into a real backend. After that I want to connect it to a real database and then learn a front-end framework such as React. I will keep practising the basics of HTML, CSS and JavaScript so they feel natural.
